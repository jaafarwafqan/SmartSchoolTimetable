# Decisions pending owner confirmation (Phase 2)

Each entry was taken autonomously while the owner was away (Phase 2 autonomy protocol 0.5). Each one is the safest option that keeps the approved architecture. Each says how to change it.

| # | Date | Decision | Alternatives | Reason | How to change |
|---|---|---|---|---|---|
| 1 | 2026-10-03 | **Shifts, lesson periods, stages and sections belong to an academic year.** Subjects, teachers and the school profile are global. | Everything global; everything per year | Spec 2.2 says a new year is created "by copying the structure of the previous one (shifts, periods, stages, sections)", which only makes sense if these are per year. Teachers and subjects persist across years. | Remove `AcademicYearId` from `Shift`/`Stage` (migration) and drop the copy option. |
| 2 | 2026-10-03 | **"Active flag" and "soft archive" are one concept:** `IsArchived` (+ `ArchivedAt`). Archived records are hidden unless "include archived" is chosen; restoring makes them active again. | Separate `IsActive` and `IsArchived` flags | Two overlapping flags would let a record be "active but archived". Spec 2.7–2.10 ask for an active flag, and section 1 asks for soft archive. | Add a separate flag and filter (migration + UI toggle). |
| 3 | 2026-10-03 | **Weekday numbering is ISO-8601: 1 = Monday … 7 = Sunday.** Defaults: working days Sunday–Thursday (7,1,2,3,4), week start Sunday (7). | 1 = Sunday; .NET `DayOfWeek` (0 = Sunday) | ISO numbering is unambiguous and matches spec 2.3 "weekdays (1-7)". Display order follows the "week start day" setting. | Change `Weekday` mapping in Domain and the UI day list (no data migration if done before real use). |
| 4 | 2026-10-03 | **Blocked periods (subjects and teachers) reference the lesson number** (1st lesson, 2nd lesson…, breaks excluded), not the row number in the periods table. | Row number including breaks | Breaks cannot be taught, so blocking a break is meaningless. Lesson numbers stay stable if a break is inserted. | Store row numbers instead and adjust validation. |
| 5 | 2026-10-03 | **Teacher limits are validated against the current year's largest shift:** max per day ≤ the most lessons any shift has per day; max per week ≤ working days × that number. If no shift or period exists yet, limits are accepted and validated when structure exists (shown as a warning). | Validate per assigned shift (teachers have no shift in Phase 2) | Teachers are global and not yet assigned to a shift; this is the safest upper bound. | Add a teacher↔shift link in Phase 3. |
| 6 | 2026-10-03 | **Dashboard "capacity gaps" = sections whose computed weekly capacity is 0** (their shift has no lessons, or there are no working days). | Workload vs capacity | Workload is Phase 3. Only real, computable data is shown (no fake statistics). | Redefine when Phase 3 workload exists. |
| 7 | 2026-10-03 | **Time zones are chosen from a fixed list of IANA zones** (Asia/Baghdad default; Gulf, Levant, Egypt, Iran, Turkey and UTC). | Free text | Prevents invalid IDs; works offline with .NET ICU time zone data. | Extend the list in `SchoolProfileRules.SupportedTimeZones`. |
| 8 | 2026-10-03 | **Until Phase 2 data exists, numerals default to Arabic-Indic and the calendar display to Gregorian** (the defaults of a new school profile). | Western digits | Matches the Arabic-first UI. The school setting overrides it immediately. | Change the defaults in `SchoolProfile.CreateDefault`. |
| 9 | 2026-10-03 | **Bell tones are synthesized with Web Audio and play only on explicit preview.** | Bundled sound files; scheduled ringing in Phase 2 | Avoid audio assets and licensing; live ringing is Phase 7. | Replace tone preview implementation and revise ADR 0018. || 10 | 2026-10-04 | **Display order of shifts and stages is a sort key, not unique.** Ties sort by name. This replaces the unique indexes from 2B and from the owner's 2C changes (migration `Phase2CDisplayOrderIndexes`). | Keep unique orders with a dedicated error code | A duplicate order was reported as a duplicate *name*, which is misleading. Unique orders also force a temporary value when swapping two rows. The intent (a clear, owner-controlled order) is kept. | Make the two indexes unique again in `SchoolSetupConfiguration` (new migration) and add a `DUPLICATE_ORDER` code. |
| 11 | 2026-10-04 | **A section cannot be created in, or restored into, an archived stage** (`STAGE_ARCHIVED`, 409). Hard delete: a stage only while it has no sections; a section always (nothing references it before Phase 3); a shift only while no section uses it. | Allow restore and hide the section; cascade-delete sections | Keeps every visible section inside a visible stage, and never deletes data silently. | Change the checks in `StagesSectionsService` and `TimetableStructureService.DeleteShiftAsync`. |
| 12 | 2026-10-04 | **Blocked periods (subjects now, teachers in 2E) must lie inside the current schedule grid:** a working day, and a lesson number from 1 to the most lessons per day of any shift in the current year. With no periods defined, no slot can be blocked. The UI drops slots that fell outside the grid (after days or periods changed) and warns before saving. | Accept 1–12 when no periods exist; keep out-of-grid slots | Rejecting invalid references is the spec rule (2.10) and the safest. Periods are defined before subjects in the setup checklist. | Relax `ScheduleGrid.Contains` (Domain) and `slotsInGrid` (UI). |
| 13 | 2026-10-04 | **Bulk add proposes short names:** the first two words of the full name, then the first three, then the full name, using the first that is unused. A line is not created when its full name already exists (likely the same person), repeats an earlier line, is too long, or no free short name exists; the preview shows why. Bulk-added teachers start without constraints. | Ask for short names per line; allow duplicate full names | Keeps pasting fast and never creates a duplicate person silently. Short names stay editable afterwards. | Change `TeacherNames.ProposeShortName` and the statuses in `TeacherBulkAdd`. |
| 14 | 2026-10-04 | **Calendar days are global (not year-scoped) and are not copied to a new year.** The "inside the current year" rule is a warning flag (`outsideCurrentYear`), never a block. A range is limited to 366 days. | Year-scoped calendar days | Spec 2.2 forbids copying calendar days, and 2.11 asks for a warning only. A global list with a computed flag satisfies both. | Add an `AcademicYearId` to `CalendarDay` (migration) and filter by year. |
| 15 | 2026-10-04 | **The demo command also refuses the configured `Database:Path`,** not only the default path. It writes only to the new file it is given. | Refuse the default path only | Protects a real database moved to a custom location. | Change `protectedPaths` in `Program.cs`. |
| 16 | 2026-10-04 | **Phone navigation opens in the page flow under the top bar** (pushing content down) instead of as a side drawer or overlay (ADR 0024). | Bottom sheet; full-screen overlay menu | The owner asked for no drawers anywhere; an in-flow menu is not edge-anchored and needs no focus trap. | Change `layout/MobileMenu.tsx`. |
| 17 | 2026-10-04 | **Calendar quick add (title + date) creates an official holiday that affects the timetable.** Kind, date range and the flag are changed with the existing centred edit dialog (3–6 fields), not by expanding the row. | Expanding rows for calendar days; asking for the kind in the quick-add row | Most calendar entries are holidays. The edit dialog already fits the 3–6 field pattern, and quick add keeps exactly two fields. | Change the defaults in `CalendarPage` quick add, or replace the dialog with an `ExpandableRow` editor. |
| 18 | 2026-10-04 | **Quick add defaults:** a subject gets the next unused palette colour (cycling after ten) and priority 3; a teacher gets a proposed short name (same rule as bulk add, #13). If no short name is free, the owner is asked to type one. | Ask for colour, priority and short name in the quick-add row | Typing only the name is the owner's requirement (§1.3). Everything stays editable in place. | `SubjectsService.NextColorAsync`, `TeachersService.ProposeShortNameAsync`. |
| 19 | 2026-10-04 | **Stage and section dialogs stay until 2.5C,** where the per-stage card with a section stepper and label generator replaces them (spec §6). | Convert them to inline rows now | Avoids building a UI that 2.5C replaces immediately. | — |
| 20 | 2026-10-04 | **Shift mode adds missing morning/evening shifts and removes unneeded ones only when no section uses them.** "Uses" includes archived sections, because the database keeps their link. An existing custom shift with the standard name («الدوام الصباحي» or «الدوام المسائي») is adopted instead of being duplicated. The impact (to create, to remove, affected sections) is previewed before applying. | Keep unneeded shifts; reassign sections automatically | Never deletes data silently, and never moves sections without the owner choosing. | `ShiftModeService.PlanAsync`. |
| 21 | 2026-10-04 | **The evening shift's proposed first lesson = the morning shift's last period end + 30 minutes.** It is the generator's default and stays editable; nothing is generated automatically. | Generate evening periods automatically | The owner keeps control of periods; the default saves typing. | `generatorStart` in `ShiftsCard`. |
| 22 | 2026-10-05 | **Copying a year also copies the active curriculum lines** of each copied stage (archived lines stay behind). | Copy only stages and sections | The curriculum is part of the structure; a new year should not start with an empty table. | `YearStructureService.CopyAsync`. |
| 23 | 2026-10-05 | **The section stepper removes only the LAST section, after a confirmation dialog.** New sections take the next unused label in the chosen style (Arabic letters, numbers or Latin letters), skipping labels of archived sections. | Remove without asking; let the owner pick which section | Removing is the only destructive stepper action; the last section is the most predictable choice. Phase 3 adds a workload check here. | `StageCardsService.SetSectionCountAsync`, `StageCardsPanel`. |
| 24 | 2026-10-05 | **Stage templates number display orders as (grade position + 1) × 10 + branch index** (for example الرابع العلمي = 10 and الرابع الأدبي = 11 in a preparatory school). An existing stage is matched by template key or normalized name; an archived match is kept and gets no sections. | Append after existing orders | Keeps grades in school order with room for manual stages in between. | `SetupTemplatesService.PlanStagesAsync`. |
| 25 | 2026-10-05 | **A curriculum cell accepts 1–15 lessons; clearing it deletes the line** (nothing references a line before Phase 3). Escape restores the saved value. | Archive on clear | Deleting keeps the table honest; archiving stays available per line through the API. | `CurriculumService.SetCellAsync`, `CurriculumGrid`. |
| 26 | 2026-10-05 | **The wizard opens automatically only once: right after a fresh account's recovery code.** Afterwards it is opened from the dashboard card «استكمال الإعداد» (until finished) or from Settings. | Redirect whenever setup is unfinished | Never interrupts an owner who prefers the screens, and never triggers on an existing database. | `startSetupWizard` in `state/session.ts`, `AppShell`. |
| 27 | 2026-10-05 | **Changing the shift mode in wizard step 1 also applies it to the current year's shifts** (when a year exists). It is refused with `SHIFT_MODE_IN_USE` while sections use a shift that would be removed, and the whole step is rolled back. | Apply the mode only in step 3 | Keeps the profile and the shifts consistent, and never moves or deletes sections silently. | `SetupWizardService.SaveSchoolAsync`. |
| 28 | 2026-10-05 | **In dual mode the shift is chosen per grade** («كل شعب هذا الصف في …»), not per section. Single sections can still be moved on the stages screen. | A shift selector per section in the wizard | One choice per grade covers the usual case with less input. | `StageTemplatePanel` (`gradeShifts`). |
| 29 | 2026-10-05 | **Wizard step 3 replaces the periods of the mode's shifts** with the generated list (a note says so when periods already exist); other shifts are not touched. | Merge with existing periods | The step is the place where the daily timing is chosen; replacing keeps it predictable and idempotent. | `SetupWizardService.SaveTimingAsync`. |
