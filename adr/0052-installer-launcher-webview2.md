# ADR 0052: M5 — the installer, the launcher, the control channel, and WebView2 (GO with a browser fallback)

- Status: Accepted (M5, branch `work/phase-5`)
- Date: 2026-10-11

## Target machines (owner decision)
Windows 10 **64-bit only** (1809 or newer), a CPU of about 3 GHz and 4 GB of RAM. There is no 32-bit edition; the installer and the launcher refuse a 32-bit Windows with «هذا البرنامج يحتاج ويندوز 64-بت». WebView2 may be missing on some Windows 10 computers.

## Decisions
1. **Two programs in one self-contained folder (win-x64, ReadyToRun, not trimmed, no .NET install).** `SmartSchoolTimetable.exe` is the launcher (a WinForms program with no console window); `SmartSchoolTimetable.Api.exe` is the local server it starts hidden. Both are published into the same folder, so the .NET runtime files are shared. Symbol files are not shipped (they carry build paths).
2. **The launcher** (`src/SmartSchoolTimetable.Launcher`): one copy per Windows session (a named mutex; a second start asks the first to show the program and ends); port 5080 when free, otherwise any free loopback port (Host, Origin and launch-token checks all use the chosen port); a tray icon with «فتح البرنامج / نسخة احتياطية الآن / إيقاف»; closing the window only hides it; a startup problem is shown in Arabic (the server writes `startup-error.txt`, ADR 0050). Command line `--tray` starts without opening the window (used by «start with Windows», off by default).
3. **The control channel** (`/api/v1/control/backup-now`, `/stop`): the routes exist only when the server was started with a control token. The launcher generates a fresh random token per start and passes it in the server's environment; no browser ever learns it. Every request also passes the Host, Origin and launch-token checks, then must present `X-Control-Token` (constant-time comparison); a wrong or missing token answers 404. The token is never logged or stored. The tray backup uses the configured backup folder.
4. **WebView2: GO, with a browser fallback.** When the WebView2 runtime (Edge) is installed the program opens in its own window; otherwise the default browser opens the same address and a tray message says why. Nothing is downloaded at install time and the installer does not bundle the runtime (it is part of Windows 11 and of current Windows 10 updates). The window shows only the server's origin: other navigation is cancelled, new windows and permission requests are refused, developer tools and autofill are off. The security model is the browser's: the same cookies, the same per-launch token, the same CSP. NuGet dependency: `Microsoft.Web.WebView2` (BSD-3-Clause, SDK only; the runtime is Microsoft's, on the computer).
5. **The installer** (Inno Setup 6, `installer/SmartSchoolTimetable.iss`, built by `tools/Build-Installer.ps1`): Arabic wizard, Program Files, desktop and Start-menu shortcuts «الجدول الذكي» and «دليل المستخدم», the application icon, version from the build (1.0.0), 64-bit Windows 10 1809+ only (`MinVersion`, plus an Arabic refusal on 32-bit), a warning below 3.4 GB of usable memory (a real 4 GB computer reports 3.5–3.9 GB), «start with Windows» off by default (an HKLM Run entry with `--tray` when chosen), a closing of a running copy first. **Upgrade in place** by running the new Setup: the files are replaced and the program's own safe upgrade runs at its first start (verified `pre-upgrade-*.db` copy, ADR 0050). **The uninstaller never deletes school data or backups** (no `[UninstallDelete]` for them; the data is in `%LOCALAPPDATA%\SmartSchoolTimetable` and the owner's backup folder); it says so when it finishes.
6. **A clean build.** `tools/Publish-Release.ps1` fails when the output holds a database, a log, a symbol file, an Excel file, a backup file, test folders or a user path. The first start on a new computer has an empty database and shows the first-run account screen.
7. **Unsigned for now.** The installer is not code-signed, so Windows SmartScreen shows «Windows protected your PC»: the user guide tells the school to choose «More info → Run anyway». **Future option:** an OV/EV code-signing certificate (paid, per year) or Azure Trusted Signing; it would remove the warning after reputation builds. Signing the launcher, the server and the installer is a one-line change in the build script (`signtool`) when a certificate exists. No certificate or secret is ever stored in the repository.

## Consequences
- The folder is larger than a framework-dependent one (about 200 MB, about 85 MB compressed in Setup) and needs no .NET install.
- The control channel is the only way the tray reaches the server; if it fails the tray says so and the program is unaffected.
- Printing and downloads (Excel, the support log) work in the WebView2 window as in a browser; the user guide describes saving a PDF from the print dialog and turning «Headers and footers» off.
